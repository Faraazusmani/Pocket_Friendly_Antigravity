# Onboarding

## Goal
Configure a local financial environment with minimal friction.

Production onboarding **composes existing use cases**. It must not contain separate financial logic, stub models, or direct table writes.

Visual prototypes with mocks are allowed earlier; production onboarding is complete only after Phase 1–11 capabilities exist (see IMPLEMENTATION_ORDER Phase 12).

## Screens
1. Name
2. Privacy introduction
3. Financial priorities
4. First account
5. Monthly income
6. Categories
7. Category budgets
8. Goals
9. Recurring payments
10. Notifications
11. Privacy confirmation
12. Completion

## Rules
- Show progress.
- Preserve entered values between steps.
- Optional setup can be skipped.
- No internet required.
- Completion opens Dashboard.
- Use shared design tokens and subtle haptic/visual completion feedback.
- Opening balance is not income; budgets and credit limits are not transactions.
